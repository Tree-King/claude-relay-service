# 對話紀錄寫入策略

本文檔說明後端新增的對話記錄行為與保存策略，便於排查請求與模型互動時的問題。

## 記錄範圍
- **非串流回應**：完整請求與回應結果會被寫入。
- **串流回應**：即使上游在中途報錯或超時，會將已收到的片段與錯誤信息一併寫入。
- **錯誤情況**：上游返回錯誤碼或訊息時，同樣生成對話紀錄，避免失真。

## 保存內容
每條紀錄包含：
- `timestamp`：ISO 時間戳。
- `model`：請求模型名，若未提供則回退為 `unknown`。
- `accountId` / `accountType`：使用的帳號與類型（例如 `standard`）。
- `isStream`：是否為串流請求。
- `clientVersion` / `serverVersion`：客戶端與服務端 Claude Code 版本。
- `request`：去除不可序列化內容的請求體。
- `response`：回應文本，對超過 8000 字元的部分會加上標註後截斷。

## 保存與過期策略
- 每個 API Key 最多保留 500 條最新紀錄，超出後自動裁剪。
- 紀錄保存 60 天，自動過期刪除。
- 遇到序列化失敗或 Redis 寫入異常時會打印警告，但不會阻塞主流程。

## 常見用途
- 後台核查請求是否按預期送達模型端。
- 比對串流過程中的錯誤片段，還原中斷原因。
- 透過版本欄位交叉檢查客戶端升級情況。
